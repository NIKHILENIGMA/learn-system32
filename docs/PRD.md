# Product Requirements Document (PRD): learn-system32

## 1. Overview & Project Scope
- **Problem:** Learning system design through static articles or passive videos fails to build intuition for real-world bottlenecks, capacity planning, queueing latency, and topology trade-offs. Learners need a hands-on environment where new system design topics (e.g., URL Shortener, Rate Limiter) can be added incrementally as they learn, tested on an interactive canvas against realistic traffic loads, evaluated for correctness ("right or wrong"), and followed by deep-dive architectural insights.
- **Solution:** An interactive, simulation-driven system design learning platform inspired by `sys0.in` ([`docs/SIMILAR_PRODUCT.md`](./SIMILAR_PRODUCT.md)). `agy` authors plug-and-play learning modules inside `src/modules/<slug>/` for each new topic, while the developer uses the interactive React Flow canvas to design architectures, run tick-based load simulations, get graded against SLA and structural requirements, and unlock rich post-completion production insights.
- **Project Scope Mode:** Mode C — Application Code Only (Modular Full-Stack Next.js 15+, Local/Self-Hosted First, Cloud-Ready Later; No Auth Wall or DevOps Overhead in v1).
- **Target Platforms:** Web Application (Next.js 15+ App Router, React 19, TypeScript, PostgreSQL + Drizzle ORM).

## 2. Target Audience & Operational Envelope
- **Primary User:** Solo developer / system design learner running the platform locally as a custom interactive learning workbench, collaborating with `agy` to generate new system design modules in `src/modules/<slug>/` as new concepts are studied.
- **Identity Model:** Zero-friction local single-learner profile persisted in PostgreSQL (no login/authentication wall or billing in v1; extensible to multi-user auth/monetization in the future).

## 4. Non-Goals (Explicitly Out of Scope for v1)
- **No Authentication or Paywall:** The platform runs locally for a single learner without login screens, OAuth setup, or payment gateways.
- **No Manual In-App Module Authoring Studio:** New learning modules are authored in code (`src/modules/<slug>/`) by `agy` rather than through a complex CMS form UI.
- **No Production Cloud DevOps / Container Sandboxes in v1:** All simulation and grading run deterministically in the pure-TypeScript engine (`src/engine/`) backed by PostgreSQL.

## 5. Success Metrics & Open Risks
- **Definition of Done (v1 MVP):**
  1. Dropping a new module folder into `src/modules/<slug>/` immediately makes it playable on the dashboard and workbench without modifying engine or UI code.
  2. The deterministic simulator accurately models bottlenecks, caching offloads, read-replica lag, and queueing latency at 60 FPS UI responsiveness.
  3. The assessment grader clearly explains *why* a design failed (e.g., *"PostgreSQL Primary overloaded at 142% capacity — add Redis Cache or Read Replicas"*) and unlocks rich insights upon passing.
- **Key Technical Risks & Mitigations:**
  - *Cyclic Graph Loops in User Designs:* Mitigated in `src/engine/simulator` via bounded topological traversal with visited-edge cycle detection and max-hop guards.
  - *React Flow Re-Render Overhead During Tick Simulation:* Mitigated by keeping live tick telemetry in a dedicated Zustand slice and updating node badges without recreating node layout objects.
